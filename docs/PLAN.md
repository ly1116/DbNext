# DbNest 桌面客户端 — 开发计划

> 基于高保真原型 `b.html`（DbNest 完整原型）落地一款**桌面级、跨平台**（Windows / macOS / Linux）的
> 一体化运维与数据库管理客户端。本文档为开发计划，记录产品定位、技术选型、分层架构与里程碑。

---

## 1. 产品定位

DbNest 面向**开发 / 运维 / DBA**，把日常运维与数据库管理工作收敛到一个客户端里：

| 能力 | 说明 |
| --- | --- |
| ① SSH 终端 + SFTP | 多标签终端、命令广播、录制、SFTP 文件树跟随终端 pwd、断点续传队列 |
| ② SQL 编辑器 | CodeMirror 语法高亮、运行、限制行数、执行计划、消息面板 |
| ③ 数据网格 | 结果集分页 / 排序 / 行内编辑 / 空值标记 |
| ④ Redis | Key 浏览、TTL、类型识别、值预览 |
| ⑤ 传输向导 | 库内 / 库间 / 库到文件 的导入导出向导 |
| ⑥ 连接编辑 | 分组、SSH 跳板、SSL、保存凭据的统一连接管理 |
| ⑦ 结构对比 | 库 / 表结构差异可视化（新增 / 修改 / 删除） |
| ⑧ 云同步 | 多端连接配置加密同步 |
| ⑨ 堡垒机 | 通过 JumpServer / 堡垒机代理接入 |
| ⑩ SFTP 全屏 | 双栏本地 / 远端文件管理器 |
| ⑪ AI 深度 | 代码 / SQL 审查、生成、一键修复，带上下文引用 |

## 2. 技术选型

| 维度 | 选型 | 理由 |
| --- | --- | --- |
| 跨平台框架 | **Electron** | 同一套 Web 技术栈产出 win/mac/linux 原生安装包，最贴合 HTML/Tailwind 原型 |
| 渲染层 | **React 18 + TypeScript + Vite** | 类型安全、HMR 快、生态成熟 |
| 样式 | **Tailwind CSS** | 原型即 Tailwind，复用设计 token 零成本 |
| 状态管理 | **Zustand** | 轻量、可在渲染进程外复用 store 逻辑 |
| 代码编辑器 | **CodeMirror 6** | SQL 语法高亮、可扩展、体积小 |
| 终端 | **xterm.js** | 业界标准 Web 终端组件 |
| 打包 | **electron-builder** | 三端签名 / 自动更新一体化 |
| 工程化 | **严格 TS + ESLint + Prettier** | 企业级一致性与可维护性 |

> 实时 SSH / 数据库 / Redis 连接依赖原生模块（`ssh2`、`ioredis`、各数据库驱动）。
> 服务层采用**可插拔适配器**：开发期使用 mock 适配器保证开箱即跑，生产适配器按文档接入。

## 3. 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│                        Electron Main 进程                      │
│  main.ts → 窗口管理 / 菜单 / 自动更新                           │
│  ipc/        → IPC 路由（connection / terminal / sftp / ai）    │
│  services/   → 业务服务（SSH / SFTP / Redis / AI / 凭据存储）    │
└───────────────┬───────────────────────────┬──────────────────┘
                │ contextBridge             │ IPC(electron ipc)
┌───────────────▼───────────────────────────▼──────────────────┐
│                       Preload (预加载)                         │
│  preload.ts → 暴露 window.dbnest 安全 API 白名单                │
└───────────────┬───────────────────────────────────────────────┘
                │ 渲染进程调用
┌───────────────▼───────────────────────────────────────────────┐
│                      React Renderer 进程                       │
│  shell/   → 标题栏 / 顶部导航 / 状态栏 / 布局                   │
│  screens/ → 11 个工作台屏幕                                     │
│  store/   → Zustand 全局状态                                    │
│  services/→ 渲染侧服务封装（调用 preload API）                  │
└───────────────────────────────────────────────────────────────┘
```

**关键约束**
- 主进程不持有 UI 逻辑；渲染进程不直接 `require('electron')`（仅经 preload 白名单）。
- 所有跨进程调用走 IPC，类型在 `shared/types` 单一来源定义。
- 凭据等敏感信息只在主进程内存 / 系统钥匙串，不进渲染进程。

## 4. 里程碑

| 里程碑 | 内容 | 交付物 |
| --- | --- | --- |
| **M1** 脚手架 | 工程初始化、主题 token、三层目录、严格类型与 ESLint | 可 `npm run web` 启动空壳 |
| **M2** 应用外壳 | 标题栏 / 顶部 11 屏导航 / 状态栏 / 布局 | 可切换屏幕的空壳 |
| **M3** 工作台 | 连接树 + 终端 + SFTP + AI 侧栏 | ① 屏幕可用（mock 驱动） |
| **M4** SQL & 网格 | CodeMirror 编辑器 + 结果网格 | ②③ 屏幕可用 |
| **M5** 连接·传输·对比 | 连接编辑 + 结构对比 + 传输向导 | ⑤⑥⑦ 屏幕可用 |
| **M6** 其余屏幕 | Redis / 云同步 / 堡垒机 / SFTP 全屏 / AI 深度 | ④⑧⑨⑩⑪ 屏幕可用 |
| **M7** 收尾 | 打包配置 + README + 注释审计 + ESLint 通过 | 完整可发布工程 |

## 5. 注释与质量规范（企业级）

- **每个模块 / 类 / 公共方法**必须写块注释或 JSDoc，说明用途、入参、返回、副作用。
- 公共 API 标注 `@since` / `@param` / `@returns` / `@throws`。
- TypeScript `strict: true`，禁止 `any`（必要时 `unknown` + 类型守卫）。
- 统一错误类型（`AppError`），集中日志（`logger`）。
- 命名语义化，禁止缩写歧义；常量集中于 `theme` / `constants`。

---

## 6. 风险与取舍

- 真实 SSH / DB / Redis 连接需原生依赖与网络，本计划以 **mock 适配器 + 清晰接口** 保证可运行与可演示，
  真实适配器作为后续增量（见 README 路线图）。
- 安装包体积较大（Electron 自带 Chromium），以 `electron-builder` 做平台分发包与按需更新。
